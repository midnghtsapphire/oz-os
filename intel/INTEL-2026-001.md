# WR_TEMPLATE_FULL causes placeholder leakage

## What we learned
The full WR template (`WR_TEMPLATE_FULL.md`, 767 lines) consistently produces
PRs with unsubstituted tokens like `{STARS}`, `{OPEN_ISSUES}`, `{DESCRIPTION}`
and bracket-placeholders like `[Yes/No]`, `[2-3 sentence summary]`. Every failed
WR in the review history (PRs #14118, #14138, #14184) was generated from this
template by `github-actions[bot]`.

The basic template (`WR_TEMPLATE_BASIC.md`, 65 lines) does not have this problem
because it has only two fields for the human and lets the research engine fill
the rest.

## Why it matters
Placeholder leakage is the #1 recurring review failure. It wastes human review
time and trains agents to check boxes (`[x]`) on sections they haven't actually
completed — creating a false-completion culture.

## How to apply it
1. Default all WR generation to `WR_TEMPLATE_BASIC.md`
2. Reserve `WR_TEMPLATE_FULL.md` for compliance/regulated work only
3. `wr-lint.mjs` now catches `{TOKEN}` and bracket-placeholder patterns
4. Custom templates (like the Oz OS WRs) bypass both templates entirely

## When it stops being true
If `WR_TEMPLATE_FULL.md` is rewritten to remove all placeholder tokens, or if
`wr-lint.mjs` catches 100% of placeholder patterns before merge, this intel
entry can be downgraded. Until then, avoid the full template.
