# Auto-merge SQUASH on agent PRs enables supply-chain risk

## What we learned
The `pr-state-orchestrator.yml` workflow enables auto-merge with squash for PRs
that pass CI. When combined with agents that generate code, this creates a pipeline
where agent-authored code can reach `main` without human review.

A malicious or hallucinating agent could introduce vulnerable code, exfiltrate
secrets via build scripts, or modify CI workflows — and the auto-merge pipeline
would land it automatically.

## Why it matters
This is the root cause of the "babysitting" problem: bad WRs land because
auto-merge has no quality gate beyond CI green. `wr-lint` was added to close
this gap for WR files, but code changes have no equivalent gate.

## How to apply it
1. Add `wr-lint must pass` as a required check before auto-merge is enabled
2. Implement AUTONOMY_TIERS.md: only Tier 0/1 changes auto-merge
3. Tier 2+ requires at least agent review; Tier 3+ requires human
4. Consider a "quarantine" label that blocks auto-merge on agent PRs touching
   workflows, secrets, or CI configuration

## When it stops being true
When AUTONOMY_TIERS.md is implemented and enforced via branch protection rules,
the risk is mitigated. Until then, auto-merge on agent PRs remains a supply-chain
vulnerability.
