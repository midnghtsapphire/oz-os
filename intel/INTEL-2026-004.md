# localStorage PAT storage in freedom-angel-repo-manager is XSS-exfil

## What we learned
The `freedom-angel-repo-manager` stores GitHub Personal Access Tokens (PATs) in
`localStorage`. Any XSS vulnerability in the same origin can read `localStorage`
and exfiltrate the token. Unlike cookies with `httpOnly` and `secure` flags,
`localStorage` has no built-in protection against JavaScript access.

OWASP explicitly recommends against storing sensitive tokens in `localStorage`
for this reason.

## Why it matters
A single XSS vulnerability (even in a third-party dependency) could compromise
the PAT and give an attacker full access to the GitHub account. This is especially
dangerous because PATs often have broad repository access.

## How to apply it
1. Never store PATs, API keys, or session tokens in `localStorage`
2. Use `httpOnly` + `secure` + `SameSite=Strict` cookies for session management
3. For client-side tools that need GitHub access, use OAuth flows with
   short-lived tokens and server-side token storage
4. Audit all product repos for `localStorage` + credential patterns
5. Prefer Doppler or environment-variable-based secret management

## When it stops being true
If browsers implement `localStorage` access control (unlikely in near term),
or if the application moves to a server-side token management pattern. The
underlying principle (don't store secrets where JavaScript can reach them)
is unlikely to change.
